C5 test build for helper directories retaining ownership from an older install.

## Fix

The 0.1.14 IPK has correct app-owned archive metadata, but the maintainer's TV
still has `helper/` owned by 1001:1001 with mode 0777 after upgrading. Setup now
recovers that specific legacy directory after verifying the app manifest and
all three root-owned, non-writable helper files against a build-time bundle pin.
Other owners, extra entries, links and modified files are refused. Only the
verified app/helper directory modes and the known legacy helper owner change;
shared installation ancestors, payload bytes and saved settings are untouched.

Install the IPK over the existing app and open Home. No SSH permission command
or configuration deletion is required for this recognized upgrade case. A
successful repair records `helper_directory_repaired`, followed by the normal
setup result, in `/var/lib/webosbrew/lg-xmb-startup.log`.

Live HDMI video is independent of this helper. Cached capture, background
controls and Home assignment still require successful helper setup. Setup
does not assign Home or enable new background restrictions. This build retains
the upper-item labels and native input names from 0.1.14.

## Validation

Unit tests exercise the reported upgrade state, repeat setup, saved settings,
unknown owners, modified bundles, unsafe files, interrupted repairs and path
replacement. A local Linux fixture with actual UID/GID 1001 and mode 0777
reproduced the old failure and passed the new loader with real helper modules.
Those tests are not TV validation. Test on the existing C5 target only; the
model/SDK gate and complete worker-output diagnostics remain outstanding.
