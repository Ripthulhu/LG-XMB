# LG-XMB 0.1.31

- New wave renderer: a WebGL 2 reconstruction of the PS3's own XMB wave, built
  from the 3.01 runtime capture (the 19x19 spring grid, the FFD programs, the
  bicubic sheet, the Fresnel lookup material and the captured particle records).
  GLSL ES 3.00 only, no WebGL 1 fallback. Without WebGL 2 it draws a static
  backdrop. See `docs/WEBGL2.md`.
- Wave colours gain **PS3 original**: the console's monthly background from the
  recovered `back_colours0` program over the 24 `month_bg` textures, following
  the TV clock or pinned to a month.
- Draws at 60 fps by default, with a **Frame rate** setting for 30. The pacing no
  longer sits on a 33 ms grid, cause the C5's rAF timestamps jitter more than the
  old tolerance allowed and every slip held a frame for three vsyncs.
- Cheaper on the C5's Mali: no preserved drawing buffer, no half-float targets,
  a mediump composite cropped to the rows the sheet can reach, and the monthly
  backdrop cached between frames. Wave FXAA Strong at 60 fps sits around 42% GPU.
- Guard columns at the sheet ends, so the oval hole at the right edge is gone.
- Menu items dim through colour alpha instead of `opacity`, so scrolling the
  menu doesn't hitch the wave any more.
- Particle density is Low / Medium / Normal (500 / 1,000 / 2,000). The capture
  holds 2,025 records, so the old 4,000 choice never drew more than that.
- The old WebGL 1 renderer, its tests and the GitHub workflows are deleted.
  Builds come from `npm run package` on a computer.

Install over the existing app without clearing settings or helper state.
The installed app ID remains `org.local.openxmb.c5` for upgrades.

Known limitations: the wave needs the local reference pack
(`app/ps3-native-data.js` and `app/ps3-background-data.js`), which is
console-derived and gitignored, so a build from the public tree alone shows the
static backdrop. Tested on an LG C5 only. Install and upgrade over 0.1.30 work;
removal and recovery weren't rerun for this build. 1.5x supersampling with Strong
FXAA at 60 fps isn't measured. Other TV/webOS combinations remain untested.

AI-assisted implementation and validation. This remains a development prerelease.
